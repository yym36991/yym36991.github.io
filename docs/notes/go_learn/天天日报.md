两条任务会不会互相踩「分片元数据」？
不会。

上传过程：是先init,后commit
每次 upload_init 都会 createTmpVersion + 独立 session，分片上传只认 自己的 session → tmpVersion，在 wtable 里是**同一文件名、不同列（临时版本）**的两套元数据

情况：A和B先后上传

支持覆盖：
他俩各自传各自的。如果B后上传完，B会覆盖A上传的。A后上传完，A会覆盖B上传的。
A 提交成功时，只删当前这次提交用的那一个 tmp 列，不会顺带删掉 B 的临时版本。因此 A 先传完并 commit 之后，B 仍可以带着自己的 session 继续传分片（只要 B 的 tmp 行还在、状态仍是上传中）。

不支持覆盖：
若一开始路径上就没有文件：A、B 的 init 都能过；A 先 commit → 当前版本变成 A 的内容；B 后 commit（finish） 时，CommitFile 里会再 checkCurrentFile，此时文件已存在且 action 仍是「不覆盖」→ EcFileExist（-66），B 的提交失败。
线上表现一般是：B 的分片可能都传上去了，但最后一笔 commit 报错，对象对外已是 A 的版本。

若一开始就有文件：A和B 在 init / precheck 阶段就会因 checkCurrentFile → EcFileExist 起不来

wos没有对整个文件做md5校验，只有对大文件的每个分片做校验



流程：大文件 = 先init（建临时版本 + session）→ 按 session 传各分片 → 后 commit/finish（把该 tmp 提交为当前版本，并删掉本任务对应的 tmp 列）。

元数据：同一路径可并存多个临时版本；分片只绑定自己的 session/tmpVersion，互不覆盖。

支持覆盖：A、B 可并行传；谁先 commit 谁先成为线上版本；后 commit 的会把当前版本换成自己的内容（几乎同时提交时靠 CAS/重试，最终仍是一个胜者）。

不支持覆盖（仅插入）
路径上还没有对象：两边都能 init；先成功 commit 的留下；后 commit 的在提交阶段 EcFileExist（-66），前面分片往往已传完，但对外仍是先提交的那份。

路径上已有对象：仅插入的请求一般在 init/precheck 就会 EcFileExist，任务起不来（除非请求本身是覆盖语义）。
