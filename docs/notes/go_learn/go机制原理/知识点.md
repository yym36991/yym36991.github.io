# 1、go语言中 uint 类型溢出问题，
<details>
  <summary> 查看/隐藏</summary>
  64位操作系统只能装下2^64-1（即 18446744073709551615），所以uint类型最大值是2^64-1，如果超过这个值，就会溢出。
  做溢出检测：如下代码。
  解决：使用更大范围的数。
</details>

```go
// 1、溢出现象
package main

import (
	"fmt"
)

func main() {
	var a uint = 18446744073709551615 // uint64的最大值
	a++ // 溢出，结果将变为 0
	fmt.Println(a) // 输出: 0
}


// 2、溢出检测
package main

import (
	"fmt"
	"math"
)

func main() {
	var a uint = math.MaxUint64 // 18446744073709551615
	var b uint = 1

	if math.MaxUint64-a < b {
		fmt.Println("溢出即将发生")
	} else {
		result := a + b
		fmt.Println(result)
	}
}


```

# 3、go语言中 什么是协程泄露（goroutine Leak?)
<details>
  <summary> 查看/隐藏</summary>
  go程序中，某些原因导致Goroutine没有被正确的管理和终止。占用系统资源但无法被回收。会引起内存增长，cpu使用率上升，导致程序崩溃或性能下降。
  原因：1、没有结束的goroutine,2、死循环，3、未处理的通道（没有及时关闭），4、错误的调度：
        在使用 sync.WaitGroup 或其它同步原语时，如果未正确实现，使得某些Goroutine没有机会完成，就会造成泄露。
  解决：1、使用defer来关闭channel，2、使用context包来管理goroutine，3、使用errgroup包来管理goroutine，4、使用sync.WaitGroup或context.WithTimeout来等待Goroutine完成。
</details>

```go
死循环：
package main

import (
	"fmt"
	"time"
)

func leakGoroutine() {
	go func() {
		for {
			// 无限循环
			fmt.Println("Leaking Goroutine") 
			time.Sleep(1 * time.Second)
		}
	}()
}

func main() {
	leakGoroutine()

	// 主程序等待一段时间后退出
	time.Sleep(10 * time.Second)
	fmt.Println("Main is exiting")
}
```

# 4、go语言中 局部变量分配堆上还是栈上？
<details>
  <summary> 查看/隐藏</summary>
  都有。
  栈上：生命周期仅限于函数内部，如简单的基本数据类型，int,folat,bool等，在函数返回后会被自动释放。
  堆上：1、当变量超出其原始作用域。如函数返回变量的指针，并在其他地方使用。
  2、对于大对象：如切片、map、结构体等，为了避免栈溢出，运行时也会考虑分配到堆上。
  3、使用关键字：new 或通过切片、映射等创建的对象通常分配在堆上。

  其他：如果函数返回局部变量的指针，但是没在其他地方使用。根据Go的逃逸分析机制，这个变量会被分配在栈上，但是如果再使用会导致未定义的行为。
</details>

# 5、go语言中 简述GC(垃圾回收)的工作原理
<details>
  <summary> 查看/隐藏</summary>
  是自动管理内存的一种方式。回收未被使用的内存以避免内存泄露。
  工作原理：
  0、根集合，从程序入口：（全局变量，栈上的局部变量，）可以直接访问的对象，都是活跃的，从这些开始追踪。
  1.0、标记：从根集合开始，遍历并标记他们。递归标记所有可达对象（通过根对象可以到达，或通过其他活跃对象可达），
  1.1、清除：未被标记的被回收内存。
  2、并发垃圾回收：和用户程序并发执行，减少暂停时间。
     GC会在程序运行时自动触发，但也可以通过调整环境变量来手动控制。例如，设置 GODEBUG=gcstoptheworld=1 可以让开发者观察GC的停顿。
  3、增量式回收：不是一次性的，分多次的。
  4、代际回收：短期存活的对象更可能被回收。
  5、与内存管理结合。保障了程序在高效利用内存的同时，尽量减少内存泄漏的发生。
</details>

# 14、go语言中 关于http包的内存泄露？
<details>
  <summary> 查看/隐藏</summary>
  1、goroutine: 如果在http请求中创建了goroutine,但是没有适当的管理他们的生命周期，如等待通道或处于阻塞状态而无法退出。
    没有退出，给他分配的有堆栈空间就不会被垃圾回收。
  2、连接泄露：使用http.Client时，创建过多Client，不重用他们，如果连接没有正确关闭，则可能导致内存泄露。
  3、没有关闭请求体。
  4、将请求的所有数据存储在内存中，特别是大文件或大量数据时，如果数据没有适当清理，造成泄露。
  5、缓存和中间件，如无限增加缓存项。

</details>

# 16、go语言中  对已经关闭的chan进行读写，会怎么样？为什么？
<details>
  <summary> 查看/隐藏</summary>
  读：如果通道关闭了，里边还有数据，就正确接着读完。如果里边没数据了，就读到通道类型的零值，不会阻塞。
  建议使用多值接收的方式判断是否已经关闭。
  这种设计的优势：不需要“读”方加额外的同步机制检查通道是否为空，是否关闭。

  写：如果已经关闭，再去写会panic.
  在写入通道之前，确保通道未关闭。可以通过同步机制（如互斥锁）或信号（如通道）来管理通道的状态。


  
</details>
使用互斥锁：避免往关闭的通道写：

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	ch := make(chan int, 3)
	var wg sync.WaitGroup
	var mu sync.Mutex
	isClosed := false

	// 启动一个 goroutine 写入通道
	wg.Add(1)
	go func() {
		defer wg.Done()
		for i := 0; i < 3; i++ {
			mu.Lock()
			if !isClosed {
				ch <- i
			} else {
				fmt.Println("Channel is closed, cannot write:", i)
			}
			mu.Unlock()
		}
	}()

	// 启动一个 goroutine 读取通道
	wg.Add(1)
	go func() {
		defer wg.Done()
		for {
			mu.Lock()
			if isClosed && len(ch) == 0 {
				mu.Unlock()
				break
			}
			mu.Unlock()

			value, ok := <-ch
			if !ok {
				mu.Lock()
				isClosed = true
				mu.Unlock()
				fmt.Println("Channel is closed")
				break
			}
			fmt.Println("Received:", value)
		}
	}()

	// 主 goroutine 关闭通道
	wg.Add(1)
	go func() {
		defer wg.Done()
		// 模拟一些操作
		fmt.Println("Closing channel")
		mu.Lock()
		close(ch)
		isClosed = true
		mu.Unlock()
	}()

	wg.Wait()
}

```

```go
	done := make(chan struct{})

			}
		}

		}

		done <- struct{}{} // 通知写入 goroutine 通道已关闭
	}()

	// 主 goroutine 关闭通道
	wg.Add(1)
	go func() {
		defer wg.Done()
		// 模拟一些操作
		fmt.Println("Closing channel")
		close(ch)
	}()

	wg.Wait()
}
```

使用条件变量：和互斥锁一起使用：
```go

package main

import (
	"fmt"
	"sync"
	"time"
)

type SharedData struct {
	mu         sync.Mutex
	cond       *sync.Cond
	data       int
	ready      bool
}

func NewSharedData() *SharedData {
	sd := &SharedData{}
	sd.cond = sync.NewCond(&sd.mu)
	return sd
}

// 写数据的 goroutine
func (sd *SharedData) Writer() {
	sd.mu.Lock()
	defer sd.mu.Unlock()

	// 更新数据
	sd.data = 42 // 假设写入的数据是42
	sd.ready = true
	fmt.Println("Writer: Data written.")

	// 通知等待在条件变量上的其他 goroutine
	sd.cond.Broadcast()
}

// 读数据的 goroutine
func (sd *SharedData) Reader() {
	sd.mu.Lock()
	defer sd.mu.Unlock()

	// 等待数据准备好
	for !sd.ready {
		sd.cond.Wait()
	}

	// 读取数据
	fmt.Printf("Reader: Data read is %d\n", sd.data)
}

func main() {
	sd := NewSharedData()

	// 启动写入 goroutine
	go sd.Writer()

	// 启动读取 goroutine
	go sd.Reader()

	// 主 goroutine 等待片刻以确保读写完成
	time.Sleep(1 * time.Second)
}

```

# 20、go语言中 闭包结构
<details>
  <summary> 查看/隐藏</summary>
	1、执行到main函数内的sum变量，Sum(1, 2) 时，Sum产生了自己的funcval结构体指针val1,保存自己的入口地址和环境信息。
	接着：在执行到匿名函数时，匿名函数会有一个自己的funcval结构体val2，在返回时，val2保存了匿名函数的入口地址，
	和捕获的自由变量a,b(合称闭包)。
	当Sum返回时，val1被回收。返回的val2（闭包）被赋值给sum变量。
 	匿名函数和捕获的自由变量a,b，一起叫做闭包。


	2、闭包的定义：指一个函数及其捕获的外部变量的组合。

	3、所有只有匿名函数并不构成闭包。匿名函数捕获它外部的自由变量之后，才变身闭包。
	4、自由变量存放在堆上。

</details>

~~~go
package main

import (
	"fmt"
)

func main() {
	sum := Sum(1, 2)
	fmt.Println(sum(1, 2))
	fmt.Println(sum(3, 4))
	fmt.Println(sum(5, 6))
}

func Sum(a, b int) func(int, int) int {
	return func(a, b int) int {
		return a + b
	}
}


type funcval struct{
    fn uniptr  //指向函数入口的指针
    extra *uint8  //指向存储数据的指针
}

~~~


# 20、go语言中 内存模型中为什么小对象多了，会造成GC压力？
<details>
  <summary> 查看/隐藏</summary>
  分代回收：小对象会被分配在年轻代中，内存区域小，分配速度快，当年轻代被填满时，GC会更频繁地启动以回收不再使用的对象。
  标记、扫描、复制、清理。数量众多，导致标记和扫描增加，导致GC压力增大。
  内存碎片。
  解决方案：减少小对象的数量，减少分配，使用对象池，
			批量分配。
			优化数据结构
			减少段声明周期的对象。

</details>

# 27、go语言中 defer原理？
<details>
  <summary> 查看/隐藏</summary>
  defer语句的作用：延迟函数调用，直到函数返回前才执行。
  defer语句的执行顺序：先进后出。
  defer语句的实现原理：编译器在编译时，会将defer语句收集到一个栈中，当函数返回时，会按照顺序执行defer语句。
  使用场景：比如延迟释放锁、关闭文件、记录日志、解锁资源等。
</details>

# 29、go语言中 主协程如何等其他协程执行完毕？
<details>
  <summary> 查看/隐藏</summary>
  1、waitgroup
  2、channel
  3、使用select 和time.After设置超时
  4、使用context.WithTimeout设置超时
  
</details>

~~~go
package main

import (
	"fmt"
	"sync"
)


func main() {
	var wg sync.WaitGroup
	wg.Add(2)
go func() {
	defer wg.Done()
	// do something
}
go func() {
	defer wg.Done()
	// do something
}
wg.Wait()
}
~~~
~~~go
func main() {
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    
    done := make(chan bool)
    
    go func() {
        // 协程的工作
        done <- true
    }()
    
    select {
    case <-done:
        fmt.Println("协程完成")
    case <-ctx.Done():
        fmt.Println("超时")
    }
}
~~~

# 31、go语言中 CAS原理？
<details>
  <summary> 查看/隐藏</summary>
  compare-and-swap，比较相等并交换，是一种无锁算法，用于多线程编程。
  
</details>

~~~go
// 原理：比较内存中的值与期望值，如果相等就使用新值替换旧值，否则返回false,原子性(不会被其他goroutine打断。)
func CompareAndSwap(addr *int, old, new int) bool {
	if *addr == old {
		*addr = new
		return true
	}
	return false
}

// 2. go中的cas实现：
package atomic
var value int32

// 原子操作：
atomic.ComareAndSwap(&value, old, new)

// 3. 常见用途
// 3.1 实现自旋锁
type spinLock struct {
	state int32
}
func (s *spinLock) Lock(){
	for !atomic.CompareAndSwapInt32(&s.state, 0, 1){
		// 自旋等待（因为state == 1,说明被其他goroutine锁住了，才会进到循环里）
	}
	
	// 避免过度cpu空转，增加退避策略
	runtime.Gosched() // 让出cpu 时间片
}
func (s *spinLock) Unlock(){
	atomic.StoreInt32(&s.state, 0)
}

// 3.2 实现无锁计数
type counter struct {
	value int32
}
func (c *counter) Inc() {
	for {
		old := atomic.LoadInt32(&c.value)
		new := old + 1
		if atomic.CompareAndSwapInt32(&c.value, old, new) {
			return
		}
	}
}
// 3.3 防止ABA问题，给目标值增加一个版本号
type versionedValue struct {
	value int32
	version int32
}
func (v *versionedValue) CompareAndSwap(old, new int32) bool {
	return atomic.CompareAndSwapInt32(&v.value, old, new) &&  // 对值进行比较并修改
		atomic.CompareAndSwapInt32(&v.version, old, new+1)    // 对版本号进行修改

}

// 4. 适用场景
// 锁竞争不激烈
// 临界区代码 执行时间短
// 多核cpu环境

临界资源：一次只允许一个进程/线程访问的资源。有共享性和互斥性
举例：共享内存、共享文件、共享变量、共享设备（打印机）
临界区：访问临界资源的代码段。互斥性，有限性（执行时间应该尽可能短）

~~~

# 32、go语言中 逃逸分析？
<details>
  <summary> 查看/隐藏</summary>
  编译器在编译时对变量分配位置的分析过程。
  栈分配：局部变量、函数调用帧、返回地址、参数、返回值地址。
  堆分配：动态申请内存，比如切片、map、结构体等。
  逃逸分析：分析变量是否逃逸到堆上，如果逃逸到堆上，则分配在堆上，否则分配在栈上。

  逃逸分析的目的：
  1、减少堆内存分配，提高性能。
  2、减少GC压力，减少内存碎片。
  3、提高程序的并发性。
</details>

~~~go
// 常见的逃逸现象
// 1. 返回局部变量
func f1() *int {
	x := 1
	return &x // x逃逸到堆上
}
func f11() int {
	x := 1
	return x // x分配栈上
}
// 2.变量大小不确定
func f2(){
	x := make([]int, 100000) // 大切片逃逸到堆上
	_ = x
}

func f2(){
	x := make([]int, 10) // 小切片分配栈上
	_ = x
}

// 3. 闭包
func f3() func() int {
	x := 1
	return func(x int) int {
		x = 2
		return x // x逃逸到堆上
	}
}

// 4. 接口
func f4(){
	x := 1
	var i interface{} = x // x逃逸到堆上
	_ = i
}


~~~

# 33、go语言中 对象在内存中的分配原理？
<details>
  <summary> 查看/隐藏</summary>
  1、基本策略：合适使用栈、堆空间。小对象分配栈，大对象分配堆。
  2、栈分配：局部变量、函数调用帧、返回地址、参数、返回值地址。
  3、堆分配：动态申请内存，比如切片、map、结构体等。
  4、逃逸分析：分析变量是否逃逸到堆上，如果逃逸到堆上，则分配在堆上，否则分配在栈上。
  5、对象大小不确定：分配在堆上。
  6、内存分配器（TCMalloc）：管理堆内存，分配、回收内存。多级缓存，内存池，垃圾回收。
		对象分配请求
			↓
		检查大小
			↓
		< 32KB → 使用 mcache（线程缓存），不需要加锁，分配速度最快
			↓
		< 1MB  → 使用 mcentral（中心缓存）
			↓
		> 1MB  → 使用 mheap（堆）
  
</details>


# 34、go语言中 内存分配原理？
<details>
  <summary> 查看/隐藏</summary>
  内存分配的基本单位：页（8KB）,内存分配器将内存分为不同的尺寸类别，从小到大依次分配。
  
  
</details>


~~~go


// 内存分配器的主要结构
type mheap struct {
	// 堆内存
	heap      heap
	// 中心缓存
	central   [numSpanClasses]struct {
		mcentral mcentral
	}
	// 页分配器
	pages     pageAlloc
}

// 线程缓存：
type mcache struct {
    // 小对象分配器
    alloc [numSpanClasses]*mspan
    // 大对象分配器
    large *mspan
}

// 中心缓存
// 当mcache没有可用的内存时，从mcentral获取
// 需要加锁
type mcentral struct {
    // 非空span列表
    nonempty mspanList
    // 空span列表
    empty    mspanList
}

// mheap（堆内存）
//当mcentral也没有可用内存时，从mheap获取
//需要加锁，锁的粒度最大
//负责大对象（>32KB）的分配
// 简化的内存分配流程
func mallocgc(size uintptr, typ *_type, needzero bool) unsafe.Pointer {
    // 1. 小对象分配
    if size <= maxSmallSize {
        // 从mcache分配
        if c := getMCache(); c != nil {
            v := c.allocSmall(size)
            if v != nil {
                return v
            }
        }
        // 从mcentral分配
        v := mcentral.alloc(size)
        if v != nil {
            return v
        }
    }
    
    // 2. 大对象分配
    return mheap.allocLarge(size)
}


~~~
# 35、go语言中 堆内存分配管理原理？
<details>
  <summary> 查看/隐藏</summary>
  go语言采用分代垃圾回收机制，
  栈分配（编译器自动分配和释放）和堆分配（垃圾回收器GC管理）
  堆内存分配的主要特点：
  1、使用TCMalloc(thread-caching malloc)策略。
  2、使用多级内存分配器，
  3、按大小类管理内存块
  4、使用span(内存段，连续的内存页)作为基本管理单位，使用page(页)作为内存分配的最小单位。

  
</details>
